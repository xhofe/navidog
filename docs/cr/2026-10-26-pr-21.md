## 3. 问题说明

### CR-01 状态栏行数

`ObjectsPanel` 在渲染时才写 `last_rows`（[objects.rs](../../crates/navidog-navigator/src/objects.rs) 818 行先清掉，863 行在详情筛选之后写入）。状态栏在 `MainWindow::render` 开头就读这个缓存（[main_window.rs](../../crates/navidog/src/main_window.rs) 663 行，[lib.rs](../../crates/navidog-navigator/src/lib.rs) 165–171 行）。目录变化时对象面板的 `observe` 会 `notify`（同文件 188–190 行），主窗口因此重画，但读到的仍是上一帧写进缓存的数字；这一帧的新数字写在子面板渲染里，不再 `notify`。选择不变时缓存一直命中，状态栏就停在旧行数。`4ba8e32` 只修正了“按筛选后的行数计数”，没有把计数从渲染里挪出来。

修法：在目录 `observe` 里算好当前选择的行数，写入 `last_rows` 再 `notify`。不要在 `render` 里改这块状态。

### CR-02 SSH 通配和撤销标记

精确主机名、`|1|` 哈希、以及“已有记录但算法不同则拒绝”是对的（[ssh.rs](../../crates/navidog-db/src/ssh.rs) 34–70 行）。russh 0.64.1 的 `match_hostname` 只做全等和哈希（`known_hosts.rs` 109–128 行），解析时把第一列当主机、第二列直接跳过（92–99 行）。因此：

- `*.example.com ssh-ed25519 …` 匹配不上，`known_host_keys` 为空，navidog 走 `learn_known_hosts` 并接受。
- `@revoked host …` 和 `@cert-authority *.example.com …` 的第一列是标记，主机名在第二列，整行被忽略，同样被当成新主机。

校验开关打开时，OpenSSH 会拒绝的主机仍可能被首次信任并追加一行。旧行为是全部接受，所以这不是相对 `main` 的放宽，而是新校验没覆盖这些行。

可选做法：

1. 连接前扫 `known_hosts`，出现通配、`!` 取反、`@revoked`、`@cert-authority` 就拒绝并提示，不 TOFU。
2. 在验收记录里写明：只支持精确主机名和 OpenSSH 哈希行；通配和撤销标记不参与判断。

**决定（2026-10-26）**：采用第 2 种。`HostKeyVerifier` 只使用 russh 的精确/哈希匹配；通配、`!`、`@revoked`、`@cert-authority` 不参与判断，可能在首次连接时被 TOFU。该限制写入 `docs/pr/acceptance-overall-review.md`。

### CR-04 动态 i18n key

`scripts/check-i18n.sh` 只校验字面量 `t!("key")`；`t!(format!("..."))` 仍需靠调用点测试。仓库内动态 key 主要集中在 `designer.*`、`col.*`、`kind.*` 等有限前缀，本轮未改成 allowlist，作为脚本限制记录。

### 存量（`main` 上已有，本 PR 没改坏）

- **S-01** [sql.rs](../../crates/navidog-db/src/sql.rs) 97 行：分隔符不是 `;` 时对每个字节做 `sql[i..].starts_with`。多字节字符走 `i += 1` 后会落在字符中间并 panic。
- **S-02** 同文件 126 行：切分语句没有 `after_identifier` 判断。`SELECT foo$tag$ FROM t; DELETE FROM u` 会并成一条。参数扫描已跳过这种标识符，切分还没有。完整词法层仍是登记中的 R-04。
- **S-03** [update.rs](../../crates/navidog/src/update.rs) 403–409 行：`C:payload.msi` 没有斜杠，检查放行。Windows 上 `Path::join` 遇到带盘符前缀的路径会换掉原目录。这次新增的私有更新目录盖不住这个名字。
- **S-04** [install.rs](../../crates/navidog/src/update/install.rs) 260 行：`tar -xzf` 解压校验过的 AppImage 包，不拒绝成员名里的 `..` 和指向目录外的符号链接。逻辑从 `main` 原样搬进新文件。
- **S-05** [navigator/mod.rs](../../crates/navidog-navigator/src/navigator/mod.rs) 630 行先 `set_items` 再 `sync_selection`。gpui-base 的 `set_items` 把 `selected_ix` 清成 `None`（`tree.rs` 221–223 行），字段行的“当前行代表这张表”判断看不到焦点，焦点回到表行。这段调用本 PR 没改。
- **S-06** [model.rs](../../crates/navidog-grid/src/model.rs) 126–128 行：数字列里 `NaN` 被当成相等，一边解析失败就退回字符串序，比较不是全序。本 PR 把数字比较收窄到数值类型，文本列不再误走 `f64`。

另外两处旧路径没有单独编号：切到多节点时 [form.rs](../../crates/navidog-connection/src/form.rs) 444 行仍 `parse().ok()`，非法端口在进入新的校验之前就被丢掉；620 行任何 `collect` 错误都切回「常规」。Linux 上 [crypto.rs](../../crates/navidog-model/src/crypto.rs) 221 行读 `machine-key` 失败会新建一把并覆盖原文件，macOS 和 Windows 走钥匙串。
