# M5 插件配置读失败保护

对应 [PR #33 的审查意见](https://github.com/xhofe/navidog/pull/33#discussion_r4458262968)。启动时读取 `plugins.json` 失败，旧实现仍会在发现插件后把空配置写回磁盘，覆盖原有授权和限额。现在保留读取错误：仍可发现插件，扫描不保存，启用、停用、重载和限额修改都不能写入。配置文件缺失仍走正常初始化。恢复配置文件后重启即可继续使用；改动不包含自动修复或迁移。

`cargo test -p navidog-plugin --test approval_persistence --locked` 先在旧实现复现了启动扫描覆盖文件。回归覆盖损坏的 JSON、不兼容版本和限额校验失败：启动扫描、再次扫描及设置操作后原文件逐字节不变，插件保持停用；恢复包含原限额的配置后，新建宿主可正常保存并保留该限额。

本机工作区测试通过 416 项。格式、Clippy（全工作区所有目标，`-D warnings`）、裸值、i18n、方言、依赖方向、`cargo deny` 和 `cargo audit` 均通过。实库测试通过 103 项，另通过查询计划三数据库测试；本次独立 Compose 项目已关闭。release 网格、导航树和 SQL 编辑器抽测均无帧超过 8.3 ms。

Metal 截图测试生成 76 张；已查看插件空页、详情、授权和限额的浅色及深色截图。
